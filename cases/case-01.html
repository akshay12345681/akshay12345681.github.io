The Stolen Szechuan Sauce

A secret recipe has leaked. With disk images, memory dumps and network traffic from a domain controller and a workstation, the job is to find how the attacker got in, where they moved, and what they took.

Scenario

A small company's most valuable secret, its Szechuan sauce recipe, has turned up somewhere it shouldn't. The domain controller and one employee workstation were imaged, memory was captured from both, and a packet capture covers the period of the suspected breach.

Questions to answer:

  • How did the attacker get in, and when?
  • What did they run, and how did they keep access?
  • Did they move from the server to the workstation?
  • What data was taken, and how did it leave the network?

Method

1. Find the way in: remote logons on the server

$ EvtxECmd.exe -d C:\evidence\DC01\Logs --csv C:\out --csvf dc01_events.csv
# Filter for 4625 (failed) then 4624 logon type 10 (RDP) from the same external IP

A burst of failed logons followed by a successful RDP session from one external address points to password guessing against an exposed server.

2. Identify what the attacker ran

$ vol -f DC01-memory.raw windows.pstree
$ vol -f DC01-memory.raw windows.netscan
$ vol -f DC01-memory.raw windows.malfind

Look for a process with an unusual name or path, a parent that doesn't fit, and an outbound connection that matches the attacker's address.

3. Check persistence

$ RECmd.exe -d C:\evidence\DC01\Registry --bn BatchExamples\Kroll_Batch.reb --csv C:\out
# Review services, Run keys and scheduled tasks created after the first malicious logon

A new service or Run key pointing at the dropped file explains how access survived a reboot.

4. Follow lateral movement and build one timeline

$ log2timeline.py --storage-file case.plaso WKS01-disk.E01
$ psort.py -o l2tcsv -w timeline.csv case.plaso "date > '2020-09-18 00:00:00'"

Logons from the server to the workstation, followed by file access on the workstation, show where the attacker went next.

5. Confirm what left the network

# Wireshark display filters
ip.addr == 203.0.113.45 && tcp.len > 0
http.request.method == "POST" || ftp-data

Matching file names and sizes in the capture against file activity on disk proves what was taken, not just what was touched.

Lessons

  • Never expose RDP on a domain controller to the internet; put remote access behind a VPN with multi-factor authentication.
  • Alert on bursts of failed logons followed by a success from the same source.
  • Monitor for new services and Run keys on servers; they rarely change legitimately.
  • Correlating memory, disk and network evidence turned "something leaked" into a precise account of what left, when and how.
