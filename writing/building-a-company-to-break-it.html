Building a company to break it.

A fictional 24-person firm on one PC, built so I could attack it, investigate it, and reset it in minutes.

01 · Why

In incident response you arrive after the damage. I wanted a network I already knew.

You almost never see a network before something has gone wrong in it. You work backwards from whatever the logs kept.

So I built one I know completely: every machine, every account, every rule. Then I know what normal looks like, and anything unusual stands out.

02 · The company

Meet Meridian Freight, a company that doesn't exist.

A logistics firm with 24 staff in six departments, each with its own file share, and a website where customers track shipments. Realistic people and permissions make the evidence look like a real company's.

03 · The network

Five rooms, one way through.

The zones never talk to each other directly. Every connection passes through one OPNsense firewall, where it can be allowed, blocked and logged. From outside, the attacker can reach exactly one thing: the website.

The forensic workstation sits on its own, outside the domain, so the evidence lives somewhere an attacker inside the network can't reach.

04 · The build

Thirteen steps in four phases, then made ready for evidence.

Every step ended with a check that had to pass, and a snapshot to come back to.

  1. Phase 1Steps 1–4

    Foundations

    • Host PC set to stay awake, with updates kept out of working hours
    • Five isolated virtual networks, one per zone
    • OPNsense firewall as the only path between them
    • Two Windows templates; every machine cloned from them
  2. Phase 2Steps 5–6

    Identity

    • The lab.local domain, with DNS, on DC01
    • Meridian Freight's 24 staff, department groups, tiered admins and service accounts, built by one script
  3. Phase 3Steps 7–10

    Services

    • File server with seven shares, each department locked to its own
    • Three staff PCs that map their drives at sign-in
    • SQL database that staff reach with their Windows sign-in
    • Shipment-tracking website in the DMZ, reading from the database
  4. Phase 4Steps 11–13

    Watch and attack

    • Wazuh SIEM to collect and search logs
    • Kali attacker on the internet side that can see only the website
    • Isolated forensic workstation, outside the domain, with the toolset
  5. FinallyDFIR-ready

    Ready for evidence

    • Logging for logons, Kerberos, account changes, share access and every command line
    • Security log raised from 20 MB to 1 GB, so evidence lasts
    • Full web server logging
    • Snapshots after every step, so any exercise resets in minutes

05 · Next

The lab is built. Now it gets put to work.

Attack it from Kali, investigate from the forensic workstation, write up what the evidence showed, then roll everything back and start again.
